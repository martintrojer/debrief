# Branches in the log

Agreed with the user (Q1–Q13, 2026-10-20).

## Problem

The log shows one history: `HEAD`'s ancestors (git), `::@` (jj), or a
`--revset`. Reviewing another branch means quitting and restarting with a
revset, and nothing on screen says which branch you are looking at. Review
output and saved sessions don't record the branch either, so an agent
receiving feedback can't tell which line of work a comment is about.

## Design

### What a branch selects

- One branch at a time. The branch is a log query parameter, like the path
  filter: picking one reloads the log. It never checks anything out;
  debrief stays read-only.
- The log shows the branch's commits not in trunk (`trunk..branch`). On
  trunk itself, or when no trunk is found, it shows the branch's full
  history.
- **Trunk:** `[log] trunk` if set, else the first of `origin/HEAD`'s
  target, `main`, `master` that exists (git); jj's `trunk()` revset alias.
- git: `git log <trunk>..<branch>`, `--end-of-options` as today. jj:
  `--revisions=trunk()..<bookmark>` (one argv element). Branch names reach
  the VCS as single argv elements, never re-parsed as flags; jj names are
  quoted as string literals in the revset.

### Which branches

- git: local branches (`refs/heads/`). jj: local bookmarks. Remote branches
  are out of scope for now.
- Listed by most recent commit first, the current branch on top.

### The selection

- **The current branch** is `HEAD`'s branch (git; none when detached). For
  jj it is the one bookmark on `@`, else the one on `@-`, else none: never
  a guess between two.
- **At start:** the current branch, or `--branch NAME`. With no current
  branch the log is the default query (`HEAD` / `::@`), labelled `HEAD` /
  `@`.
- **`--revset` / `[log] revset`:** a branch replaces it. When one is given,
  the picker has a `revset: <R>` entry that switches back to it.
- **The picker (`<leader>b`, both screens):** the branch list as the review
  pickers draw it (typed filter, `C-n`/`C-p`, Enter picks, Esc closes). The
  current branch is marked, the selected one highlighted. The list starts
  with an entry for the default query (`HEAD` / `@`), then `revset: <R>`
  when one is set.
- **Picking:** the log reloads with the branch. The page limit goes back to
  the start limit; the cursor stays on its commit if it is still listed,
  else goes to the first row. The path and text filters are kept.
- **In the commit view:** the open diff stays open; only the commit list
  swaps. If the open commit is not on the new branch it stays open, no row
  is marked open, and `]]` / `[[` step from its old place, as the path
  filter does.
- **A selected branch that goes away** (deleted, renamed) on a reload: the
  log falls back to the current branch and the status line says
  `branch <name> is gone`.
- `r` and watcher reloads keep the branch. A watcher reload also refreshes
  the branch list.

### Showing it

- **Top row** in the log and the commit list's rule: `⎇ feat/x` (or
  `⎇ HEAD` / `⎇ @` / `⎇ revset: R`), beside the `⌕ path` chip when both are
  set. It always shows, so the history you are looking at is always named.
- **Status line** on both screens: `branch: feat/x` before `path:` and the
  counts. When space runs out it elides after the text filter and the path.
- **Commit view header:** the branch after the short ID, dim.
- Branch labels on each log row (`git log --decorate` style) are out of
  scope for now.

### Working copy

- git's working-copy row shows only when the selected branch is the
  checked-out one (or none is selected). jj's `@` row shows only when `@`
  is in the query's result, as today.
- `[view] follow_working` and the tree watcher follow the same rule.

### Review output

- `debrief_review::Rev` gains `branch: Option<String>` (serde default,
  skipped when `None`), so files written before it still read.
- A comment records the branch selected in the log when it was made: the
  context it was reviewed in, not every branch containing the commit.
  `None` for the default query and for a revset.
- Export: each item gets `- Branch: feat/x` after `- Revision:` when set.
  Per item, because one batch can span branches.
- `debrief-review` 0.5 (new public field). ramble bumps to it; ramble's own
  working-copy comments carry no branch yet.

### Saved sessions

- `Session` gains `branch: Option<String>` (serde default). Sessions stay
  one per commit: the same commit under two branches is one review.
- Saving records the selected branch. Opening a session from `<leader>rs`
  switches the log to its branch first; when that branch is gone it opens
  in the current log and the status line says so.
- The session picker shows the branch on each entry.

### Config and CLI

- `--branch NAME`; `[log] trunk = "main"` overrides trunk detection.
- `--branch` with `--revset` is a usage error (exit 2).
- An unknown `--branch` is an error at start (exit 2), as an unknown revset
  is.

## Changes while building

- git trunk: a branch named like trunk (`main` for `origin/main`) shows
  its whole history even when ahead of trunk, not just its unpushed
  commits. jj likewise for a bookmark tracked by the trunk remote.
- jj: with no remote `trunk()` is the root commit, so a local `main` or
  `master` bookmark is trunk, matching git's fallback.
- jj bookmark names are read with `stringify(name)` (the template's
  `name` prints jj's quoted form for names needing quotes) and passed as
  `bookmarks(exact:"…")` string literals.
- The picker starts on the listed entry. A branch with no commits (an
  unborn `HEAD`) starts on the default history instead of failing.
- The commit view header drops the branch when it would crowd the subject.

Review panel (2026-10-20), each fixed with a regression test:

- Branch names are checked as exact refs (`show-ref --verify`); `main~1`
  was accepted as a branch.
- Only a missing branch (`NoSuchBranch`) falls back to the current one; a
  trunk error keeps the selection. git pins trunk by commit ID in the
  query, so a deleted trunk ref leaves the last good query working.
- A session's branch is the one its commit was opened (or last changed)
  under, not the selection at save time (quit-save after switching
  mislabelled sessions). Under the default history or a revset none is
  recorded.
- Opening the working copy's session after a branch switch waits for git's
  working-copy row, read on a worker, instead of reporting it missing.
- `[log] revset` stays in the picker when `--branch` starts the log.
- `- Branch:` escapes control characters: a jj bookmark name holding a
  newline or CR could fabricate review items in the agent-bound markdown.
- `[view] follow_working`: a follow load landing during `V` or the
  comment box is dropped, and a change seen meanwhile reloads when they
  close.
- `set_selection` and `set_path` share one `requery` helper.

## Out of scope

Remote branches, several branches at once, branch labels on log rows,
checking out or creating branches, per-branch seen state (seen stays per
commit and change), sessions keyed by branch, ramble recording branches.
